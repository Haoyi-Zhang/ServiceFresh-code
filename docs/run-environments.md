# Retained run environments

## Reference campaign

The retained reference results predate environment capture. The package records a Linux runner, one sequential worker per phase, a four-core scientific-intake entitlement, a 4-GiB memory limit, no configured swap at intake, and source code that narrows each phase to the minimum CPU in the inherited affinity mask when `sched_getaffinity` is available. It does **not** record the exact Python implementation or version, CPU model or architecture, Linux distribution/kernel or execution image, inherited mask, or selected CPU identifier. Those fields are marked `not recorded` in `results/reference/environment.json`; metadata from a later machine is not substituted.

The reference timing columns are therefore descriptive retained observations. Stable semantic files and non-timing table fields remain reproducible, but exact absolute timing reproduction is not claimed. Build, checker, and matched full-cache setup each have one timing observation per scale case. Only warm-query columns summarize five batch means.

## Clean reproduction

The post-repair clean run is generated by the delivered `reproduce.py`. Each phase records the precise Python implementation/version and executable, CPU architecture/model exposed to the process, OS distribution/kernel, inherited and post-set affinity masks, and selected logical CPU. `results/clean/environment.json` summarizes those phase records. Its metadata applies only to that clean execution and is not evidence about the older reference campaign.

The clean run compares 23 discrete result files and the non-timing fields of 18 case tables with the reference. Timing equality is intentionally excluded.
